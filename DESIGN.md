# official-manef: design direction

## What this is

A GitHub profile README. Its reader is someone who arrived from a link, a search, or
another repo, and gives it a few seconds before deciding whether MANEF builds anything
real. The page has one job: show one shipped product with evidence, then let the reader
leave or follow a link.

## Direction

A title card, not a brochure. The page opens with the name, one line of what the studio
does, and three ways in. Then it shows one product with a screenshot of the running app.
Everything else is one short list of public repos. The restraint is the point: a profile
page that is mostly badges and stat cards reads as activity theater, and a reader who
notices that stops trusting the rest.

Badges are allowed only in the three-link header row, where each one is a real
destination (site, org, mail). The rest of the page is text and one image.

## Palette

The page renders in GitHub's own theme, in both light and dark, and cannot override it.
There is no token table to declare: colours come from the viewer's GitHub theme, and the
only values this repo controls are the three badge backgrounds.

| element | value | source | note |
|---|---|---|---|
| header badges | `#111111`, `#181717`, `#2B2B2B` | this file, shields.io `for-the-badge` | white label on near-black, well above 4.5:1 |
| body text | GitHub theme foreground | the viewer's theme | not controlled here |
| product screenshot | `manef.dev/images/catalog/baton.webp` | built site | one image, real UI |

Both light and dark are the viewer's choice, so the dark `source` element on the snake
picture is the only theming this repo does.

## Type

- Whatever GitHub renders: the system UI stack for body text, and GitHub's own heading
  scale for `#` and `<h2 align="center">`.
- No custom fonts. A profile README cannot load one, and asking for one would be a lie.
- The `<h1 align="center">` name and the `<strong>` subtitle are the only size decisions.
  Everything else is body size.

## Dial

```
ENERGY  1   /* a title card. No visual claim beyond the name and one screenshot */
RHYTHM  1   /* header, product, repo list, snake. One column, fixed order */
MOTION  1   /* the contribution snake animates on GitHub's side; nothing here moves */
```

## Motion

Nothing in the README animates. The contribution snake is an animated SVG generated by
the workflow on the `output` branch; it is the one moving element and it comes from
GitHub Actions, not from this file. It is decorative, it carries no claim, and it sits
last so it cannot push the product below the fold.

## Allowed

- Three header badges, each a real destination.
- One product section with a screenshot of the running app.
- A short "repositori publik terpilih" list, all public, all shipped.
- The contribution snake, at the bottom, as a closing mark.

## Forbidden

- Third-party stat, streak, or activity cards. They render someone else's service's
  interpretation of this account, and they crowd out the product.
- A badge wall (fourteen tech logos). A stack list is not evidence of shipping.
- A link to a private or nonexistent repo. It reads as a 404 to every visitor.
- A product claim with no working URL behind it.
- An invented metric, customer name, or screenshot.
- Em dash in shipped copy.

## Where it lives

`README.md` is the whole design. `.github/workflows/snake.yml` generates the one
animated asset. There is no stylesheet, no component, and no build step.
